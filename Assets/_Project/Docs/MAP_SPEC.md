## 1. 레퍼런스 & 룩 목표
- 참조: 건전 스크린샷의 **레이아웃 문법** — ①맵(바닥+벽)이 화면 중앙, ②벽 바깥은 완전한 어둠, ③벽은 "높이가 있어 보이는" 탑뷰 2.5D 착시, ④바닥은 톤 다운, 발광 요소(우리는 마젠타)가 대비로 튐
- **에셋 유용 금지** — 건전 타일 모방 불가. Franuka 반입 팩(던전 타일셋 포함, 슬라이스 완료)으로 구성
- 색 규율: 맵은 무채색~저채도 (바닥 진회색, 벽 회백색). **마젠타는 지형에 절대 사용 금지** (AI 위협 전용색 계약)

## 2. 좌표 (D5 구현 확정값 — 빈칸이던 초안을 실측으로 채움)
| 항목 | 값 | 근거 |
|---|---|---|
| 전투방 내부 (바닥) | **32 × 18** | 🔴 계약 #2 개정 (2026-08-08 사람 지시). 아래 "24×14에서 바뀐 이유" 참조 |
| 시작방 | 전투방과 동일 32 × 18 | 규격 1종으로 통일 — 프리팹·빌더 분기 제거 |
| 보스방 | 전투방과 동일 32 × 18 | 보스 패턴 튜닝 보존 |
| 복도 | 길이 **10** × 폭 **5** | 순수 통로 (문답 확정). 폭 5는 플레이어 지름 0.8의 6배로 병목 없음 |
| 벽 두께 | 충돌 **1u** (시각 2단 §4는 미구현 — §11) | 건전풍 높이 착시 |
| Grid Cell | 1×1 = 타일 16px, **PPU 16** | 16px = 1u 정합. 캐릭터 PPU 18과 별개 (카테고리별 PPU) |
| 문 개구부 | **5u** (복도 폭과 동일) | 이동 병목 방지 |
| 방 간 원점 간격 | **42** = 방 폭 32 + 복도 10 | 빌더가 `RoomSpacing`으로 계산, 수작업 스냅 불필요 |
| 체인 원점 | y = **−200** | 폴백 아레나(원점)와 공간 분리 — 토글 OFF 경로 보존 |
| 방 수 | **8** = 시작방 + 전투방 6 + 보스방 | 전투방 N ↔ 웨이브 N 1:1, 보스방 = 웨이브 7 |

**24×14 → 32×18로 바뀐 이유 (이 스펙 초안 대비 변경):**
화면이 26.67×15u(ortho 7.5 · 16:9)라 **24×14 방은 화면 안에 통째로 들어온다.** 그 상태로는 추적 카메라가 클램프에 걸려 한 픽셀도 움직이지 않아 §7의 `CameraConfiner`가 무의미해진다. 방이 화면보다 커야 추적이 성립하므로 32×18로 확대했고, 스폰 링도 반폭 12×7 → **16×9**(인셋 1 → 링 15×8)로 동반 조정했다. §7의 "반폭 12×7 그대로"는 이 결정으로 **무효**다.

- 방 배치: 월드 좌표에 **일렬 수평 체인** (시작방 → 전투방 1…6 → 보스방). 수직 배치·꺾임 없음 — 미니맵 없이도 방향 상실 불가능하게

## 3. 타일맵 레이어 구성 (Grid 1개 + Tilemap 4개)
| Tilemap | Sorting Layer | 역할 | 콜라이더 |
|---|---|---|---|
| `Floor` | Ground (최하) | 바닥 타일. 방 테마별 색 변주 | 없음 |
| `Walls` | Walls | 벽 하단(충돌 라인). **`ProjectileBlocker` 태그/레이어** — 탄이 벽에 소멸 | TilemapCollider2D + **CompositeCollider2D** (Rigidbody2D Static) |
| `WallTops` | WallTops (플레이어보다 위) | 벽 상단 캡 — 높이 착시용, 충돌 없음 | 없음 |
| `Decor` | Ground 위 | 균열·해골·이끼 등 비충돌 장식. 방당 5~10개만 (과밀 금지 — 탄 가독성) | 없음 |

- Sorting Layer 순서 (아래→위): `Ground < Decor < Shadow < Units(플레이어·적·상자) < Walls < WallTops < Projectiles < VFX < UI`
  - **Projectiles가 벽보다 위**: 탄·마젠타 조준선이 벽에 가려지면 심리전 정보 손실 — 조준선 전체 렌더 계약과 동일 취지
- CompositeCollider2D는 Geometry Type = Polygons. 방+복도 전체 벽이 콜라이더 몇 개로 병합 → WebGL 성능 안전

## 4. 벽의 높이 착시 (건전풍 핵심)
탑뷰인데 벽이 서 있어 보이는 표준 기법 — **벽 1칸 = 세로 2타일 시각**:
```
■ WallTops  ← 벽 "윗면" 타일 (플레이어 머리 위에 그려짐, 통행·탄 모두 불가 구역의 캡)
█ Walls     ← 벽 "앞면" 타일 (돌 표면 텍스처, 여기에 콜라이더)
░ Floor     ← 바닥
```
- 북쪽 벽: 앞면(Walls)이 화면에 보이므로 2단 모두 배치. 남쪽 벽: 앞면이 안 보이는 방향이므로 WallTops 1단 + 콜라이더만
- 플레이어가 벽 뒤로 반쯤 가려지는 연출은 WallTops의 Sorting Layer가 자동 처리 (Y-sort 불필요 — 벽이 직선뿐이라)

## 5. 맵 바깥 어둠 처리 (질문의 핵심)
**라이트를 쓰지 않는다** (동적 라이트 금지 계약). 3겹 레이어링으로 해결:

1. **베이스 = 무(無)렌더**: 카메라 Background = Solid Color `#0A0A0F` (완전 검정보다 살짝 푸른 암흑 — 순수 #000은 Bloom 대비가 죽음). 맵 바깥엔 타일을 아예 안 깐다 → 자동으로 어둠
2. **경계 감쇠**: 벽 바깥 1~2칸에 **가장자리 그라데이션 타일** (검정→투명 알파, 자체 제작 4방향+코너 9슬라이스 1세트) — 벽과 어둠이 칼같이 끊기지 않고 스며들게. Sorting = `Shadow` 레이어
3. **실내 톤 다운**: Global Light 2D 1개의 Intensity **0.85~0.9** (1.0보다 살짝 어둡게) + 바닥 타일 자체를 저명도로 — 이래야 마젠타(HDR+Bloom)와 주황 탄이 스크린샷처럼 튄다

- ❌ 하지 않는 것: 플레이어 주변 시야 라이트(동적 라이트 금지), 안개/전장의 어둠(선형 맵이라 불필요), 스프라이트 마스크 비네트(비용 대비 효과 미미 — 폴리싱 여유 시만)

## 6. 문 (Door) 스펙
| 상태 | 시각 | 충돌 | 전이 |
|---|---|---|---|
| **Open** | 개구부 + 열린 문틀 스프라이트 | 없음 (통행 가능) | 플레이어가 문 안쪽 트리거 진입 → 방 활성화 |
| **Locked** | 닫힌 문 스프라이트 + 저채도 붉은 램프 (마젠타 금지!) | BoxCollider2D ON + ProjectileBlocker | 방 전멸 → Open 전환 (0.3s 애니, SFX 훅) |

- 문 프리팹 1종: `Door.cs` — `SetLocked(bool)` 공개 API만. 방 상태 로직(`RoomController`)이 호출, 문은 스스로 판단하지 않음
- 방당 문 최대 2개 (입구/출구). 시작방은 출구 1개, 보스방은 입구 1개 (진입 후 영구 잠금 — 보스전 이탈 불가)
- 진입 잠금 타이밍: 플레이어 트리거 진입 → **입구 문 즉시 Locked** → 0.5s 후 스폰 시작 (문 닫히는 연출을 볼 시간)

## 7. 방 프리팹 구조 (RoomRoot)
```
Room_N (프리팹)
├── Tilemaps (Floor/Walls/WallTops/Decor — 방 로컬)
├── Doors (입구/출구 Door 프리팹 참조)
├── EnterTrigger (문 안쪽 1u 라인)
├── SpawnArea (기존 스폰 링 정의 — 반폭 12×반높이 7, 인셋 1 그대로)
├── ChestAnchor (방 중앙)
└── RoomController — 상태: Dormant → Active(락인·스폰) → Cleared(문 개방·상자)
```
- `RoomController`가 기존 `WaveManager`에 "이 방 = WaveConfig_N" 매핑을 알림 — **WaveManager 내부 로직 무변경** (스폰·전멸 판정 그대로), 트리거 주체만 "상태 전환"에서 "방 진입"으로
- `CameraConfiner` 데이터: 방+인접 복도의 카메라 클램프 사각형을 RoomRoot가 보유 → 추적 카메라가 현재 구역 값으로 Lerp 클램프
- **방 내부 장애물·기둥 배치 금지** (전투 지형 변화 금지 계약 + 적 FSM이 장애물 회피 없음 — 코딩봇 돌진이 벽에 박히는 참사 방지). Decor는 전부 비충돌

## 8. 성능·빌드 가드 (WebGL)
- 전 맵 상시 활성 OK (방 9개×타일 수백 장 = 문제 규모 아님). 단, 렌더 부하보다 **탄 가독성**이 우선 — Decor 과밀 금지
- 타일셋 아틀라스: Franuka 팩 시트 그대로 (개별 스프라이트 분리 반입 금지 — 드로우콜·빌드 크기)
- CompositeCollider 병합으로 벽 콜라이더 수 최소화. 빌드 크기는 D-2 WebGL 빌드에서 확인 (목표 <50MB 여유 예상)

## 9. 제작 절차 (에디터 빌더 관례 준수)
1. `DungeonSetupBuilder` (신규 Editor 도구): Grid+4 Tilemap+Sorting Layer+방 프리팹 뼈대를 결정론 생성 — 기존 Setup 빌더 체계에 편입 (Font 빌더 마지막 재실행 규칙 유지)
2. 방 1개(24×14) 골드 프리팹 완성 → 복제 후 테마 타일만 교체 (방 7개 수작업 금지)
3. 검증 스모크: ① 탄이 벽에 소멸하는가 ② 코딩봇 돌진이 벽에서 Recovery로 전환하는가 ③ 조준선이 벽 위에 그려지는가 ④ 문 Locked 중 플레이어·탄 통과 불가한가

## 10. 컷 라인 (일정 압박 시 버리는 순서)
