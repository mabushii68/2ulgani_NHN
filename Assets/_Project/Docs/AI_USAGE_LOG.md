## 2. 대표 프롬프트 & 구조 설명 (최종 문서 직행 후보)

> 최종 PDF의 "AI 대상 주요 프롬프트 및 지시 사항" 절에 그대로 실을 후보만 엄선. 각 항목은 아래 형식.

### 2.1 회피 예측기(AIBrain) 구현 — "짧은 프롬프트 + 계약 문서" 방식
- **일차/세션**: D1 세션 6
- **목적**: 게임 정체성의 핵심인 §7 회피 심리전(온라인 조건부 확률 모델 + 피격 위기 이벤트)을 순수 C#으로 구현
- **프롬프트 원문**:
  ```
  정식 폴더로 인정하고 추가하셈.
  AIBrain도 시작하자
  ```
- **결과 및 특기사항**: 이 6글자 지시로 8개 클래스와 51건 자체 검증이 나왔다. 설계 판단의 근거는 프롬프트가 아니라 **`GDD.md` §7과 `CLAUDE.md`의 🔴 계약 절**이었다. AI가 스스로 내린 판단 중 사람이 확인해야 할 것 2건을 분리해 보고: ① GDD 미명시인 `ThreatMissRadius` 추가(없으면 10유닛 옆을 지나는 탄도 트리거되어 표본이 오염됨), ② 피격 시 방향을 학습하지 않는 선택(§7.1이 학습을 성공 분기에만 명시).
- **선정 이유**: **계약을 프롬프트가 아니라 문서로 강제한 사례.** 특히 "Laplace 가상 카운트 (1,1) 고정"이라는 🔴 계약을 지키기 위해, 규칙 2("모든 수치는 SO")를 기계적으로 따르는 대신 **그 값만 `const`로 못박고 나머지는 SO로 열되 이탈 시 `OnValidate` 경고**를 넣는 판단을 AI가 스스로 했다 — 두 규칙이 충돌할 때 어느 쪽이 상위 의도인지 문서에서 읽어낸 것. 또한 `UnityEngine.Vector2` 대신 자체 `Vec2`를 만든 결정("AIBrain은 Unity 없이 검증 가능해야 한다"는 규칙 3의 문자 그대로 이행)이, 하필 같은 날 MCP 런타임 검증이 막힌 상황에서 **유일하게 자동 검증이 가능한 영역**을 만들어 냈다.

### 2.2 개정안 검토 — "읽어보고 어떤지 말해줄래?"가 산수 반증으로 이어진 사례
- **일차/세션**: D5 세션 1
- **목적**: 사람이 새로 쓴 던전 개편 개정안(v1.1)의 타당성 검토
- **프롬프트 원문**:
  ```
  Assets/_Project/Docs/GDD_AMENDMENT_v1.1.md, CLAUDE_v1.1.md 새로 추가했거든.
  게임의 단조로움을 없애고자 새로 작성했는데, 읽어보고 어떤지 말해줄래?
  ```
- **결과 및 특기사항**: 문서를 요약·수용하는 대신 **수치를 검산했다.** 개정안이 "ortho 7.5를 유지하면 24×14 방에서 화면 밖 영역이 생긴다"를 전제로 계약 3건(추적 카메라 / 오프스크린 화살표 / 예측탄 온스크린 게이트)을 세웠는데, 실제로는 가시 영역이 26.67×15u라 **방이 통째로 화면에 들어온다.** 즉 세 계약이 전부 무효이고, 계약 #1(추적)과 #2(방 규격 고정)가 서로를 상쇄하는 구조였다. 같은 검토에서 "조준선 전체 렌더"는 이미 LineRenderer라 **공수 0**임도 분리했다.
- **선정 이유**: **AI가 사람 문서의 전제를 반증한 사례.** 코드가 아니라 기획 문서를 대상으로, "좋아 보이는 제안"과 "성립하는 제안"을 렌더 파이프라인 수치로 갈랐다. 이 검토가 없었다면 방 안에서 한 픽셀도 움직이지 않는 카메라와 절대 발동하지 않는 화살표를 마감 2일 전에 구현했을 것이다.

### 2.3 계약과 지시가 충돌할 때 — 규칙을 어기지 않는 이행 경로 찾기
- **일차/세션**: D5 세션 2 · 세션 9
- **프롬프트 원문**:
  ```
  지금 현재 씬에서 쓰이는 에셋들이 회색인데, 별로 이쁘지도 않고 의미가 없음.
  색깔 있게 다시 수정하고 이제 회색으로 하지 마셈.
  ```
  ```
  어느 곳엔 기둥과 벽같은게 있고, 오브젝트가 있고 이런거. 에셋으로 채워넣어봐 알아서
  ```
- **결과 및 특기사항**: 두 지시 모두 표면적으로는 🔴 계약과 충돌했다.
  ① **회색조 폐기** — 회색조는 "마젠타 = AI 위협" 계약을 방어하려고 도입한 것이었다. 그런데 GDD §10.4 조문을 다시 읽으니 "그 외 위협은 **무채색~주황**"이라, 적을 주황·갈색으로 컬러화하는 것은 **조문 범위 안**이었다. 계약의 실체가 *마젠타 예약*이지 *무채색 강제*가 아님을 문서에서 분리해 지시를 그대로 이행했다.
  ② **방 안 기둥** — 계약 #2와 MAP_SPEC §7이 금지하는데, 금지 사유가 형식이 아니라 실제 고장이었다(적 FSM에 장애물 회피가 없어 코딩봇 돌진이 박히고, 탄이 막히면 위기 이벤트가 안 생겨 학습 표본이 줄어든다). **비충돌 장식으로 만들어** "보이는 것은 기둥, 동작은 안전"으로 이행하고, 진짜 충돌 기둥은 승인 대상으로 분리했다.
- **선정 이유**: 계약 준수를 "지시 거부"가 아니라 **"조문을 정확히 읽어 이행 가능한 경로를 만드는 일"** 로 다룬 사례. 같은 세션에서 이 작업이 CREDITS의 라이선스 준수 논거를 무효화한다는 부작용까지 스스로 찾아 정정했다.

| D5 | **암반 배경(Bedrock)** — 방 확대 + 카메라 여유 때문에 벽 너머가 검게 뚫려 보이자, 체인 전체를 덮는 어두운 타일 필드를 깔아 메웠다 | 다음 세션에 `MAP_SPEC.md`를 읽으니 **그 검은 영역이 의도된 것**이었다(§1-② "벽 바깥은 완전한 어둠", §5-1 "맵 바깥엔 타일을 아예 안 깐다 → 자동으로 어둠"). 건전풍 레이아웃 문법의 핵심을 내가 메워 없앤 셈이라 철회했다 | **"결함처럼 보이는 것"과 "스펙"을 구분하려면 스펙을 먼저 읽어야 한다.** 나는 사람이 그 문서를 IDE에서 열기 전까지 존재를 몰랐고, 그동안 스펙에 반하는 방향으로 한 세션을 썼다. 하위 스펙 문서가 생기면 상위 문서(CLAUDE.md)에 포인터를 박아 두는 것이 이런 낭비를 막는다 |
| D5 | **Sorting Layer 9종 생성 — 겉으로는 성공, 실제로는 4종이 죽어 있었다** | `uniqueID`를 이름 해시로 만들었는데 int 캐스팅에서 **음수로 넘친 값은 Unity가 조용히 0(=Default)으로 무효화**한다. 목록에는 이름이 보여 성공으로 착각했고, 이어서 **Global Light 2D의 Target Sorting Layers가 생성 이전 목록만 갖고 있어** 새 레이어의 모든 렌더러가 빛을 못 받아 화면이 전부 검게 나왔다 | **"만들었다"와 "작동한다"를 가르는 것은 렌더 결과였다.** 두 결함 모두 API가 예외를 던지지 않고 조용히 실패했고, 배선 검사(레이어 이름 조회)도 통과했다. 렌더 캡처를 검증 수단으로 갖고 있지 않았다면 원인을 잘못 짚었을 것이다 — D3에서 얻은 "화면이 막히면 파일을 읽는다"의 역방향으로, **파일이 맞는데도 틀릴 때는 화면을 봐야 한다** |
| D3 | **화면 캡처로 Unity를 직접 보려는 시도** (세션 4) — 사람이 "네가 플레이 모드 들어가서 스크린샷 찍어 확인하라"고 지시. PowerShell로 화면 캡처 + `SetForegroundWindow`로 Unity 창 전면화 | Windows가 백그라운드 프로세스의 창 전면화를 차단해 Unity가 앞으로 나오지 않았다(캡처된 건 사람이 보던 브라우저). 해당 세션은 MCP 미연결이라 Play 진입·콘솔 조회도 불가. D1 세션 5의 "백그라운드에서는 게임 루프가 안 돈다"까지 겹쳐, 설령 전면화에 성공해도 신뢰할 수 없는 화면이었다 | **화면이 막히면 파일을 읽는다.** ttf 바이너리 파싱(unitsPerEm 1200 확인) → 폰트 애셋 YAML(`m_AtlasRenderMode: 4118` = RASTER) → 씬 YAML(폰트 GUID 33개·크기 분포) 3단으로 원인을 특정했다. 특히 **"고쳤다고 한 SMOOTH 전환이 실제로는 실행되지 않았다"**(값이 4118 그대로)를 파일로 잡아냈다 — 사람의 "여전히 깨짐"이 수정 실패인지 미적용인지 구분되는 지점이었다. 시각 확인은 못 해도 **"무엇이 적용되었는가"는 전부 파일에 있다** |
