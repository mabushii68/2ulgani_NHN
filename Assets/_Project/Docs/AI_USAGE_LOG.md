## 2. 대표 프롬프트 & 구조 설명 (최종 문서 직행 후보)

### 2.1 회피 예측기(AIBrain) 구현 — "짧은 프롬프트 + 계약 문서" 방식
- **일차/세션**: D1 세션 6
- **목적**: 게임 정체성의 핵심인 §7 회피 심리전(온라인 조건부 확률 모델 + 피격 위기 이벤트)을 순수 C#으로 구현
- **프롬프트 원문**:
  ```
  정식 폴더로 인정하고 추가하셈.
  AIBrain도 시작하자
  ```
- **결과 및 특기사항**: 이 6글자 지시로 8개 클래스와 51건 자체 검증이 나왔다. 설계 판단의 근거는 프롬프트가 아니라 **`GDD.md` §7과 `CLAUDE.md`의 🔴 계약 절**이었다. AI가 스스로 내린 판단 중 사람이 확인해야 할 것 2건을 분리해 보고: ① GDD 미명시인 `ThreatMissRadius` 추가(없으면 10유닛 옆을 지나는 탄도 트리거되어 표본이 오염됨), ② 피격 시 방향을 학습하지 않는 선택(§7.1이 학습을 성공 분기에만 명시).
- **선정 이유**: **계약을 프롬프트가 아니라 문서로 강제한 사례.** 특히 "Laplace 가상 카운트 (1,1) 고정"이라는 🔴 계약을 지키기 위해, 규칙 2("모든 수치는 SO")를 기계적으로 따르는 대신 **그 값만 `const`로 못박고 나머지는 SO로 열되 이탈 시 `OnValidate` 경고**를 넣는 판단을 AI가 스스로 했다 — 두 규칙이 충돌할 때 어느 쪽이 상위 의도인지 문서에서 읽어낸 것. 또한 `UnityEngine.Vector2` 대신 자체 `Vec2`를 만든 결정("AIBrain은 Unity 없이 검증 가능해야 한다"는 규칙 3의 문자 그대로 이행)이, 하필 같은 날 MCP 런타임 검증이 막힌 상황에서 **유일하게 자동 검증이 가능한 영역**을 만들어 냈다.

> 시도했으나 폐기한 AI 활용 (예: §14.1 ML-Agents 착수 후 폐기). 최종 문서에 "시도와 판단" 서사로 활용.

| 일차 | 시도 내용 | 폐기 사유 | 배운 점 |
|---|---|---|---|
| D1 | **ML-Agents + Sentis 보스 이동 정책** (GDD §14.1) — 사전 훈련 강화학습(에디터 훈련 → ONNX → Sentis 런타임 추론 → WebGL). AI 기술 문서를 "온라인 확률 학습(심리전) + 사전 훈련 심층 RL(보스 이동)" 2단 구성으로 만들려던 설계 | **미착수 확정.** 착수 조건이 "D8 WebGL 검증 통과 + 잔여 1.5일 이상"이었으나, D1이 2026-08-04로 확정되면서 마감(8/10)까지 7일뿐임이 드러나 D8 자체가 달력에서 사라졌다. 훈련은 반나절에 끝나는 작업이 아니라는 것을 GDD 작성 시점에 이미 명시해 뒀고, 그 판단이 그대로 적용됨 | 착수 조건을 **날짜가 아니라 "잔여 기간"으로 못박아 둔 것이 실제로 방어에 성공했다.** 조건이 "D8에 한다"였다면 일정이 밀린 상태에서 무리하게 시작해 훈련도 게임도 못 끝냈을 것이다. 스트레치 목표에 정량 착수 조건을 붙이는 것이 컷 판단을 감정이 아니라 산수로 만든다 |
| D1 | Unity MCP `execute_code`로 씬을 코드 구성 (세션 2) | 서버 측 BOM 삽입 버그로 모든 코드가 컴파일 실패(`Line 1: ﻿`). codedom 백엔드였고 Roslyn 미설치 | 우회(`[MenuItem]` + `execute_menu_item`)가 **결과적으로 더 나았다.** 씬 구성이 재실행 가능한 스크립트로 남아 참조 누락 버그를 고친 뒤 그대로 재생성할 수 있었다. 도구가 막혔을 때 "같은 일을 하는 다른 경로"를 찾으면 부산물로 재현성이 붙는 경우가 있다 |
| D1 | `ProjectSettings.asset` YAML 직접 편집 (세션 4, 사람이 허가함) | Unity가 메모리에 들고 있는 PlayerSettings 값으로 파일을 덮어쓸 수 있음 | 사람이 허가해도 **더 안전한 경로가 있으면 그쪽을 택하고 이유를 말하는 것**이 맞다. `PlayerSettings.*` API + `AssetDatabase.SaveAssets()`로 우회 |
| D1 | MCP로 플레이 모드 런타임 검증 자동화 (세션 5) | **Unity 창이 백그라운드면 에디터가 게임 루프를 틱하지 않는다.** 플레이 모드 진입은 되지만 프레임이 0장 — `runInBackground=true`로도, PowerShell 포그라운드 강제로도 해결되지 않음 | 진단 근거를 먼저 만든 것이 컸다: 스폰 텔레그래프 0.5초가 6초 뒤에도 안 끝났고 `[MenuItem]`은 실행됐다 → "에디터 콜백은 도는데 게임 루프만 안 돈다"로 좁혀져, **내 코드 버그가 아니라 하네스 한계**임을 확정할 수 있었다. 이 구분을 못 하면 없는 버그를 쫓는다. 결론: **입력이든 시간이든 런타임 거동은 사람 검증을 전제로 설계하고, 자동화는 코드 경로 직접 호출(`[MenuItem]` 스모크)까지만 기대한다** |
